Swarm memory is not reducible to the sum of context windows. Agents store and pass on knowledge through files, claim graphs, repositories and the shared environment. Three results need to be kept apart:

- **Working beyond the window.** External memory helps a single agent too; by itself this is not a swarm advantage.
- **Joint accumulation of knowledge.** In Anthropic's experiment with Opus 5.5, answer accuracy from the team's notes rises from 0.53 for one agent to 0.70 for ten and 0.74 for a hundred ([Ch. 4](#w-opus55-card)). This is answer accuracy, not a measurement of memory capacity.
- **Pooling distributed facts.** Knowledge spread across members does not guarantee a correct shared answer.

The chapter moves from the limits of the native window and a single agent's external memory to shared swarm artefacts, the pooling of distributed facts, and population and environment memory.

## The native window grew; reasoning over it did not

A long window covers storage and retrieval, but not reasoning over the whole window. The Claude Opus 4.6 measurements below separate those two jobs. Quality falls with length even inside the window: in 2025 Chroma described "context rot" across 18 models (the longer the input, the less reliable the answer, and unevenly across positions), and LOCA-bench (HKUST, February 2026) showed an agent's accuracy dropping fast as its context grows from 8 to 256 thousand tokens with the task held fixed, with a clear benefit from context management (both works are in the table at the end of the chapter). This is the niche the swarm lays claim to: not fitting more in, but not losing the thread.

:::short opus46-launch-cluster
lead: Claude Opus 4.6's window grew to 1 million tokens: retrieving eight "needles" scores 76.0% (MRCR v2), but a multi-step graph task of the same size reaches only F1 38.7–41.2 (GraphWalks).
On 5 February 2026 Anthropic released Claude Opus 4.6 with a 1 million-token window (beta): on MRCR v2 with eight "needles" in about a million tokens of text the model scores 76.0% at maximum effort with adaptive thinking, against 18.5% for Sonnet 4.5 with a 64 thousand-token thinking budget; the settings differ. But on a multi-step graph task of the same size (GraphWalks BFS) its F1 is only 38.7–41.2. Multi-agent search in the system card (an orchestrator with no tools of its own and subagents with windows of 200 thousand tokens each) reaches 86.57% on BrowseComp against 83.73% for the best single agent, and 92.5% against 91.3% F1 on DeepSearchQA; the number of subagents and the token counts are not disclosed. "Agent teams" in Claude Code remain an experimental feature with a permanent lead, a shared task list and mailboxes. Storage is solved; reasoning over the whole window is not.
:::

## Memory through many calls: a single agent beyond the window

Memory beyond the window does not require a swarm. The text is moved into the environment (a variable, a file, a directory), and the model reads it in chunks, calls itself on fragments, or edits its own context as a document; this way a single agent already works with corpora of millions and trillions of tokens. These works show that "effective memory" exceeds the window by orders of magnitude, and they set the bar for a swarm: if one agent with a file system already handles a corpus of trillions of tokens, swarm memory has to deliver something beyond that.

:::card recursive-language-models
lead: The model keeps text in a variable and calls itself on chunks of it: over a corpus of 6–11 million tokens (22–40 times GPT-5's window) it answers correctly 91.3% of the time; the sub-calls do not communicate with each other.
Alex Zhang, Tim Kraska and Omar Khattab (MIT CSAIL), in "Recursive Language Models" (preprint, 31 December 2025), put the long text in a variable inside an environment where the model runs Python. The root model sees only the length and the beginning of the text, writes code that searches and filters it, and from that code calls a language model, itself or a cheaper one, on individual chunks. Sub-calls return strings, know nothing about each other, and in the main experiments ran one after another. The memory is the variable plus the code that reads it, not a conversation among copies of the model.

On BrowseComp-Plus with 1,000 documents (6–11 million tokens, 22–40 times GPT-5's window of 272 thousand), RLM(GPT-5) answers correctly 91.3% of the time. GPT-5 itself cannot take the input.

- An agent with BM25 retrieval scores 51.0%, and a compaction agent 70.5%.
- On OOLONG-Pairs, where the answer depends on almost every pair of lines, F1 rises from 0.1 for GPT-5 to 58.0 at depth 1 and 76.0 at depth 3.
- Quality still falls with length, only more slowly: on OOLONG the RLM drops from 84.5% at 8 thousand tokens to 46.0% at 1 million, and GPT-5 from 92.1% to 31.1% already at 262 thousand.
- The median gain across four tasks is +26% over the compaction agent, +130% over CodeAct with sub-calls, and +13% over Claude Code (on Claude Opus 4.1). Against the OpenCode coding agent on the same GPT-5 the margin is about 2%.

Cost per query is on average comparable to the base model, with a heavy tail.

Those baselines sit on the same GPT-5, so the gain is not a stronger model in disguise. It is still not a swarm. Sub-calls do not communicate, there is no speed-up (RLMs take longer), and much of the effect comes from moving the text into a programmable environment. The test sets are small (20–150 examples), the runs are single and without intervals, and the tasks are mostly synthetic. On short inputs the plain model is better. Deep recursion helps GPT-5 on the hardest task but mostly hurts Qwen3-Coder, and an independent reproduction (CUHK) found that depth 2 lowers accuracy. NeurIPS 2026 acceptance is according to the author's blog.

:::short coding-agents-long-context
lead: A single coding agent with a directory of text and ordinary commands beats the best published numbers on four of five long-context benchmarks (samples of 200 examples); a search index more often hurts it.
Weili Cao, Xunjian Yin, Bhuwan Dhingra and Shuyan Zhou (Duke), in "Coding Agents are Effective Long-Context Processors" (preprint, 20 March 2026), give a single agent, Codex on GPT-5 or Claude Code, a directory with the text and ordinary commands: file search and Python. On samples of 200 examples, best configuration vs best published number: BrowseComp-Plus 88.50 vs 80.00, Oolong-Synthetic 71.75 vs 64.38, Oolong-Real 37.46 vs 24.09, Natural Questions (a corpus of about 3 trillion tokens) 56.00 vs 50.90; on LongBench-v2, 62.50 vs 63.30. The average of +17.3% is a mean of relative gaps, and Oolong-Real contributes more than half of it. A search index more often hurts: Codex without one scores 88.50 on BrowseComp-Plus, with BM25 78.50; the coding agent also beats the recursive RLM. An argument for a single agent's file-based memory, not for a swarm; some of the "best published" numbers were obtained on the full sets.
:::

:::short context-language-models
lead: The model edits its own context as a file: an agent on Qwen3.6-27B with a 32 thousand-token window scores 59.4% on BrowseComp-Plus; the only swarm experiment, with 6 agents, was run once.
Rulin Shao and 12 co-authors at the University of Washington and Meta Superintelligence Labs, in "Context Language Models" (preprint, 29 September 2026), keep the context in a file that the model edits itself through bash, instead of a transcript compressed by an external harness. Without fine-tuning, an agent on Qwen3.6-27B with a 32 thousand-token window scored 59.4% on BrowseComp-Plus (11.4% higher than the best summarization baseline, at lower compute). The only swarm experiment: 6 GPT-5.6-Sol agents, one per repository, optimize interdependent Python packages for more than a day; the speed-up on held-out tests is 1.044× vs 1.026× for a swarm with summarization at the same spend. Subagents barely help: 44.2 vs 44.6 with a 32 thousand-token window, and only at 128 thousand 50.2 vs 47.3, at about +54% compute. The preprint is dated 29 September 2026; the swarm was run once.
:::

:::short recursive-agent-optimization
lead: A model trained to spawn copies of itself with a clean window solves 95% of synthetic tasks with an 8 thousand-token window vs 24% for a single agent; on DeepDive recursion is about 18 times slower.
Apurva Gandhi, Aviral Kumar and Graham Neubig (CMU), with Satyaki Chakraborty and Xiangjun Wang (Amazon AGI Labs), in "Recursive Agent Optimization" (preprint, 7 May 2026), train a model to spawn copies of itself with a clean window. The copy starts with an empty window, so the parent does not have to keep the child's scratch work. On synthetic crafting, a recursive agent with an 8 thousand-token window solves 95% of tasks and 88% of hard ones, almost as well as with a 256 thousand-token window, while a single agent at 8 thousand stays at 24% and 0%. When the single agent's window is large enough, it still solves only 20% of hard tasks against 88%, and on hard tasks solved by both, recursion is 2.5 times faster. On Oolong-Real the reward rises from 0.203 to 0.320 and on DeepDive success from 0.24 to 0.40, but there, on tasks solved by both, recursion is about 18 times slower and spends 561 thousand tokens vs 20 thousand. The prompt encourages delegation; the models are Qwen with 4 and 30 billion parameters.
:::

Six more works of the same family are collected, with their numbers, in the table at the end of the chapter: MemAgent (the agent reads text in chunks and rewrites a short memory), Context-Folding from ByteDance Seed (folding a subtask into a brief summary), Recursive Agent Harnesses from PwC and Prime Agent from Prime Intellect, Princeton and MIT (recursive subagents), Cursor's Composer 2 (training together with chains of self-summaries), and Anthropic's engineering blog, which in September 2025 reduced practice to three techniques: context compaction, structured notes outside the window, and subagents with a clean context that return a brief summary.

## Shared artefacts in real swarms

When there are many agents working for weeks, memory is no longer the window but what lies between agents: a claim graph, a repository, a shared folder, an index of notes. In 2026 such memory held several swarms together, and each case shows its cost. An example of accumulation is the knowledge base that up to 100 Opus 5.5 agents build in a day ([Ch. 4](#w-opus55-card)): nearly all of the gain in answer accuracy on it comes by 10 agents, and going from 10 to 100 adds only 4 pp. [Cursor](#w-cursor-scaling), whose swarm wrote SQLite, explains its success by context efficiency: "We suspect the ability to scale the agent swarm comes from this context efficiency, more than from parallelism itself." A planner never implements and never clutters its window with details, a worker never plans, and a shared Field Guide is curated by the agents themselves; this is the author's hypothesis, without an ablation. [Kimi K2.5](#w-kimi-agent-swarm) calls its swarm "proactive context management": each helper works in its own window and returns a single result. As early as 2025, Anthropic engineers wrote that the lead agent of their Research system stores its plan in external memory because context beyond 200 thousand tokens is truncated ([Ch. 4](#w-anthropic-multi-agent-guidance)). Below are Anthropic's enzyme-discovery campaign, where a dedicated agent maintains the shared knowledge base, and four more works that make such external memory an object of study. Last comes a UK AI Security Institute tool that shows which agent read another agent's record.

:::card anthropic-art-enzymes
lead: A campaign of Claude Mythos 5 agents with a shared knowledge base found a new branch of enzymes in 21.5 hours, but the decisive detail was seen by one worker that read the raw DNA; 10 reruns missed it.
Anthropic, in the report "Autonomous AI agents discover reverse transcriptases with tandem repeat arrays" (23 September 2026; Peter H. Yoon, Januka S. Athukoralage, Emmanuel Ameisen and colleagues), tasked its agent system with finding new reverse transcriptase systems, enzymes that copy RNA into DNA, in a metagenomic protein database. Every role was played by Claude Code with Claude Mythos 5. Humans set the structure: five stages of the brief with scripted checks, worker–supervisor pairs, and a report editor. Memory was a shared version history plus a knowledge base that a "curator" agent updated after each task; relevant entries from it were injected into the prompts of later agents.

In 21.5 hours without human intervention the run produced 119 tasks (98 of them opened by the agents themselves), 949 sessions and 215.6 million tokens, excluding cache reads. The announcement's "roughly 950 agents" is the sum of short sessions in different roles: the system allowed at most 58 at once, and on average 3–4 were running (our estimate). The find was a new branch of ART enzymes with an array of CRISPR-like repeats. The decisive step was taken by one worker that read raw DNA in its own window: neither the brief nor the task assignment asked about repeats. In 10 reruns of the same campaign the array was never noticed. In a test of single models on the already found data, the strongest models found the array in at least 90% of attempts when the DNA was placed directly in the prompt, while working through files and tools the share fell to as low as 32% (Opus 5).

The shared base carried leads between sessions, and the detail was still seen only by the agent that read the raw data itself. The hierarchy was set from above (Chapter 5), and there is no "single agent" or "team without a lead" control (Chapter 4): this is an application example, not a scaling measurement. This is a company report without peer review: the brief, the code and the skill library are unpublished, the lab experiments were done by humans, and, by the authors' own account, the enzyme's activity and the system's function have not been shown. Mario Rodriguez Mestre (University of Copenhagen) says his group studied these enzymes for years and discussed unpublished data with Claude; Anthropic replies that it knows of no publications on the system and did not train on users' conversations.

:::short fermat-last-theorem
lead: "Dozens" of Claude agents wrote a Lean 4 proof of Fermat's Last Theorem (13 million lines) in 11 days once they switched to the shared Prove2Me claim graph; there is no single-agent control.
Anthropic (blog, 4 September 2026; the project was led by Tianyi Peng, whose group at Columbia University builds Prove2Me): "dozens" of Claude agents, from 7 to 17 August 2026 (11 days), wrote the first complete machine-checked proof of Fermat's Last Theorem in Lean 4: 29,511 theorems, 13 million lines, about 6 billion output tokens; checked by the Lean kernel and by the independent nanoda kernel. The first attempts failed: agents "quickly lost track of the project's state and stopped collaborating effectively" (their work still accounts for about 7% of the final non-boilerplate lines). What held the later work together was Prove2Me, a shared dependency graph. Each node is a statement plus a description in ordinary language; an agent reads that graph, checks another agent's statement, and only then tries to prove it. The authors call the graph "particularly helpful for mitigating memory degradation". There is no single-agent control, the effects of model and platform are confounded, and the number of simultaneous agents and the cost are not disclosed; the proof relies on Mathlib.
:::

:::short agora-git-memory
lead: Shared agent memory as a Git commit graph: 13 workers took a frozen model from 3.3923 to 1.899 bits per byte, but about 98% of the reduction came in the first six hours.
Eight NVIDIA authors, among them Yifan Zhang and Yi Dong, in "Agora: Git as Shared Memory for Collective AutoResearch" (preprint, 16 September 2026), built shared agent memory as a Git commit graph: every result, failure and check references its parents, and there are no roles. From 26 April to 8 May 2026, 13 workers (eight of them on Claude Opus 4.7, GPT-5.5 and GPT-5.4; the models of the other five were not recorded) took a frozen model from 3.3923 to 1.899 bits per byte (62% of the way to a trained GPT-2 124M), leaving 1,703 contributions, including 165 checks; the winner's lineage is 145 commits from 15 accounts. Almost all of the gain came in the first six hours: the first 18 scored contributions closed about 98% of the reduction, after which the search narrowed into a single branch, and on 2 May humans changed the prompt of eight workers. The gain per unit of compute was not measured: v1 proposed four equal settings, and v4 removed that table.
:::

:::short coral
lead: Long-running agents with a shared memory of attempts and notes: four agents without roles reached 1,103 cycles on Anthropic's kernel task vs 1,350 for one agent, at the cost of 596 evaluations vs 56.
Ao Qu, Han Zheng, Zijian Zhou and colleagues at MIT, NUS and SMART, in "CORAL: Towards Autonomous Multi-Agent Evolution for Open-Ended Discovery" (COLM 2026, preprint April 2026), replace fixed evolutionary search with long-running agents that share a memory of attempts and notes. A later agent can start from a commit another agent already made. A single agent on Claude Opus 4.6 is not worse than OpenEvolve, ShinkaEvolve and EvoX on any of 11 tasks (strictly better on 9) and is strictly above the previous record on 6. Four agents without roles on Anthropic's kernel task reach 1,103 cycles vs the previous record of 1,363 and 1,350 for one agent; the best of four independent runs stays at 1,180; 66% of the new records grew out of another agent's commit. Without accumulated notes and skills, a single agent degrades from 1,350 to 1,601 cycles. The price: 596 evaluations vs 56, and the share of successful ones falls from 43% to 9%; the claimed number of new records does not match the table.
:::

:::short delm-shared-context
lead: Peer agents without a lead write findings into a shared context: on SWE-bench Verified, at the same cost of $0.24 per task, two DeLM agents score 63.72% vs 55.26% for AOrchestra (Gemini 3 Flash).
Yuzhen Mao, Azalia Mirhoseini and colleagues at Stanford, in "Decentralized Multi-Agent Systems with Shared Context" (preprint, 9 June 2026), remove the lead agent. Peer agents take tasks from a queue and write findings into a shared context, so the next agent inherits the finding without inheriting the search that produced it. On SWE-bench Verified with Gemini 3 Flash, two-agent DeLM and AOrchestra cost the same, $0.24 per task, while accuracy is 63.72% vs 55.26%; four agents give 66.08% at $0.47. On ten long Terminal-Bench 4.0 tasks, two agents on Claude Opus 5.5 score 93.33% vs 81.67% for Claude Code, in 64.77 minutes vs 130.75, and cheaper ($17.91 vs $20.31); with GPT-6-Astra they are more accurate but more expensive ($13.65 vs $9.01). Reading the shared context costs 1.7–3.7% of spend on Opus 5.5 and 7.7–17.7% on GPT-6-Astra; without any one of the coordination mechanisms the speed-up disappears. The ten tasks were selected for long Codex run times; with four agents, Terminal-Bench 4.0 accuracy drops by 3–4 points.
:::

:::short aisi-transect
lead: An open-source tool from the UK AI Security Institute links a plan, code or draft written by one agent to its later reading by another; it shows knowledge transfer in a team but does not measure its benefit.
The UK AI Security Institute, in the blog post "Transect: Making large-scale agentic evaluations easier to understand" (7 October 2026), describes an open-source tool for analysing the transcripts of multi-agent runs and demonstrates it on a six-day research run. Transect links a plan, code or draft written by one agent to the later reading of that file by another. Recorded events, token use and model-generated activity labels share one timeline, with links from each label back to the original transcript passage. The report itself separates observation from interpretation: the order of entries does not establish that agents worked at the same time, a worker's instructions do not establish its actual role, and reading a file does not establish influence on a decision. The tool does not measure any gain in team quality. [The code is open](https://github.com/AI-Safety-Institute/transect).
:::

## When distributed knowledge does not add up

A second difficulty for swarm memory is not length but distribution. If facts are spread across agents, the swarm has to gather them, and for that someone has to ask what the others know. Two benchmarks from 2026 conferences (ICML and ACL) expose different failures of knowledge exchange: in HiddenBench, agents fail to elicit others’ unique facts; in Silo-Bench, they often answer before gathering the data or fail to converge. Two more works compare shared and private memory directly, on different tasks: in a code ablation, private memory scores slightly higher than a shared pool; on BrowseComp-Plus, a shared store with search scores higher. An engineering view of the same problems comes from a Caura.ai and Ben-Gurion University group (table at the end of the chapter): the shared memory of an agent fleet breaks in four ways, and an evaluation of their production service recovered all provenance chains of depth 4 but found an isolation bypass and a conflict in the order of checks.

:::short hiddenbench
lead: When facts are spread across agents, groups answer correctly 30.1% of the time vs 80.7% for one agent with all the facts; forcing all facts to be revealed in the first round raises accuracy to 92.6–98.2%.
Yuxuan Li, Aoi Naito and Hirokazu Shirado (Carnegie Mellon), in "Systematic Failures in Collective Reasoning under Distributed Information in Multi-Agent LLMs" (HiddenBench, ICML 2026), took the "hidden profile" task from social psychology: each agent has shared facts and its own unique piece, and the correct answer is visible only to someone who puts everything together. On 65 tasks, groups of 3–4 agents (GPT-4o, 4.1 and 5, Gemini 2.5, Qwen3, Llama 4) answer correctly 30.1% of the time vs 80.7% for a single agent with the full set of facts. Forcing all facts to be revealed in the first round raises accuracy to 92.6% for GPT-4.1 and 98.2% for Gemini-2.5-Flash: agents can combine facts, but they do not ask on their own what the others know. For GPT-4.1, adding agents does not help (a gain from discussion of +0.348 with three, +0.006 with seven). A short "exchange facts, then decide" protocol (Exchange-Decide) gives 0.73–0.80. Models from 2024–2025, no Claude.
:::

:::short silo-bench
lead: When data are split across agents, the success of DeepSeek-V3.1 teams falls from 61.2% with two agents to 18.1% with a hundred; agents often submit an answer before collecting the data.
Yuzhe Zhang and colleagues at the Beijing University of Technology, Zhejiang University, Meituan and ETH Zürich, in "Silo-Bench: A Scalable Environment for Evaluating Distributed Coordination in Multi-Agent LLM Systems" (ACL 2026), distribute data across 2–100 agents of one model (DeepSeek-V3.1, GPT-OSS-120B, Qwen3-Next-80B-A3B): each holds its own piece, and every agent must output the exact answer to an algorithmic task. Mean success is 36.9% for DeepSeek, 16.9% and 8.2% for the others; for DeepSeek it falls from 61.2% with two agents to 18.1% with a hundred, and on tasks with a full data shuffle it is zero at 50 or more agents, while a single agent with all the data solves them 26.7% of the time (GPT-OSS; its 50-agent team: 0%). Agents build fitting structures on their own (a star, a chain of neighbours), but submit an answer before collecting the data (37.2% of analysed runs) or fail to converge (29.9%). Each configuration was run once, the models are open, and the tasks are exact computations.
:::

:::short scaling-teams-or-time
lead: Growing a team from 1 to 7 agents raises the composite score unevenly (Claude Sonnet 4.5: from 57.78 to 62.21), and in an ablation shared memory was slightly worse than private memory (48.62 vs 49.43).
Shanglin Wu, Kai Shu and colleagues at Emory, Illinois Tech, Notre Dame and Cisco Research, in "Scaling Teams or Scaling Time? Memory Enabled Lifelong Learning in LLM Multi-Agent Systems" (preprint, 27 March 2026), compare team size with accumulating experience through LLMA-Mem memory on MultiAgentBench. On 16 research tasks, teams of 1, 3, 5 and 7 agents give Claude Sonnet 4.5 a composite AAS score (the mean over a task sequence of the running mean; the score also includes a communication rating) of 57.78 / 58.96 / 62.57 / 62.21: it rises overall, but five agents score slightly above seven, and for Qwen3-32B three agents (59.21) beat five (58.45); tokens grow at every step, for Claude from 53.5 thousand to 344 thousand per task. The memory cuts spend by 9.4–71.7% relative to other memory systems, not relative to working without memory. The key result: in an ablation (code, Qwen3-32B) a shared store was slightly worse than private memory (48.62 vs 49.43), and a hybrid was lower still (46.92). The ceiling is seven agents.
:::

:::short scalemas-substrate
lead: Four identical Qwen3.5-9B agents with the shared ScaleMAS store answer 55.1% of BrowseComp-Plus questions correctly, versus 46.8% with private stores and 38.0% for independent agents.
Zhenting Qi and colleagues at FAIR (Meta) and Harvard, in "Scaling Multi-Agent Intelligence with Substrate-Centric Coordination" (preprint, 12 October 2026), remove addressed messages: an agent does not choose whom to write to. It publishes a result to a shared store, searches it by content, and opens the records it finds by address. A record holds a subtask, its artefact, a rationale and references to earlier results. Search returns a bounded number of records, ranked both by the text of the query and by how often other records have built on them; frequent citation is a retrieval signal, not a check of truth. The informative control keeps four identical agents and changes only access to the records. On BrowseComp-Plus (Table 2) the shared store gives 55.1% successful answers, a private store for each agent 46.8%, and independent ReAct agents without a store 38.0%. Shared access adds 8.3 percentage points over private stores, and the whole mechanism adds 17.1 points over independent attempts. This is one control at equal team size, not at equal compute; it does not show that any shared memory pays. In a separate comparison at roughly 20 million tokens per example, eight ScaleMAS agents reach 60.0% and sixteen [DeLM](#w-delm-shared-context) agents 26.0%. Scaling depends on the task: contradiction detection keeps improving up to 128 agents, while FATE-M theorem proving plateaus at around 16. The authors' own Contradiction Audit uses a relaxed metric that does not penalize extra reports. What is bounded is a single read, not an agent's total context or spending, since it may read many times. The paper does not establish a law for the growth of long-term memory capacity across hundreds of participants.
:::

## Population memory and environment memory

Memory can also be kept outside the agents: in an archive of other agents' trajectories, from which a new agent retrieves relevant experience, or in the world itself, where traces and structures remain. A CMU and Berkeley group tested the first approach, an MIT lab the second, on societies of up to 200 agents. Both yield gains, but neither measures how such memory grows with the number of agents. A third work, from UCLA, tests what the persistent storage of past reasoning buys, and separates it from savings in the working context. Other forms of shared memory (the Kosmos "world model", AgentFlow's growing memory shared by roles, and the exchange of hidden vectors in Latent Collaboration) are collected in the table at the end of the chapter.

:::short multi-agent-transactive-memory
lead: A shared index of trajectories from dozens of models raises success on ALFWorld from 0.4708 to 0.6431, but on WebArena only from 0.1818 to 0.2045; this is population memory, not a live swarm.
To Eun Kim, Fernando Diaz, Negar Arabzadeh and colleagues at CMU and Berkeley, in "Multi-Agent Transactive Memory" (preprint, 18 June 2026), pool trajectories of dozens of different models into a shared index. The next agent retrieves a piece of past experience from that index instead of living through the earlier run. On ALFWorld mean success rises from 0.4708 without retrieval to 0.6431 with an SVMRank reranker, steps fall from 11.77 to 10.35, and success grows monotonically with index size; on WebArena the rise is only from 0.1818 to 0.2045, and the size curve dips at half the index and reaches 20.9% on the full one. When retrieving only from other task types, ALFWorld gives 0.5985. This is population memory, not a live swarm: 77.82% of the ALFWorld index consists of trajectories of a trained seq2seq model from the benchmark's authors. The index is skewed, but what is read from it is more diverse: in version 2 (15 October 2026, Appendix H, Table 5) that source supplies 25.6% of SVMRank retrievals, while 31 minority sources occupy 1.4% of the index but supply 40.7% of SVMRank retrievals; pooled across retrieval methods, they supply 31.8% of retrievals. A removal ablation has still not measured the dominant source's causal contribution; variances are not reported.
:::

:::short persistent-memory-controlled-ablation
lead: Splitting a long context among agents cuts the peak KV cache per query to 14.3 MiB from 35.5, while memory of past reasoning changes accuracy by +0.015 with an interval from −0.011 to +0.046: no distinguishable gain.
Hochan Son and colleagues at the University of California, Los Angeles, the University of Wisconsin and HCLTech America, in "Persistent Memory in Multi-Agent LLM Inference: What It Costs, What It Buys, and When You Can Tell" (preprint, 6 October 2026), separate two things often called by the one word "memory": splitting a long context among agents, and persistent storage of reasoning traces with search over them. In the first part, the CoA-PKV scheme reduces the peak KV footprint per query to 14.3 MiB, against 35.5 for single-pass reading and 35.3 for RAG with the same retrieval volume. These are token-derived estimates from the model's geometry, not total GPU memory; cumulative KV traffic instead rises by about 1.6 times. In the second part, enabling recall changes accuracy by +0.015 with a 95% interval from −0.011 to +0.046 and adds 0.368 MiB of peak cache. Excluding questions on which either arm failed lowers the estimate to +0.003; the authors do not rule out an effect of the order of runs. Recall could have helped on only about a quarter of the questions, and independent questions supplied with their own evidence are a poor test of transfer between episodes, so the paper does not show that memory is useless. The boundary that follows: savings in the working context, the existence of stored traces and the useful reuse of past experience have to be measured separately.
:::

:::short prev-swarmworld
lead: In a shared environment where up to 200 agents leave structures, shared worlds yield more validated inventions (5.75 and 7.00 vs 2.75), but the strongest single artefact stays with isolated search.
Subhadeep Pal, Fiona Y. Wang and Markus J. Buehler (MIT), in "SwarmWorld: Stigmergic technological evolution in societies of language-model agents" (preprint, 26 August 2026), put identical gpt-5.6-luna agents without roles into a shared 72×54 grid. The agents leave structures that contain executable programs, and those programs are tested after the agents are removed. The largest society is 200 agents in one world. The memory is stigmergic: a trace left in the world, not a message sent to a teammate. By tick 3,200 (100 agents), shared worlds give portfolio resilience of 0.2474 and 0.2365 against 0.1794 for the control (the best of N isolated single agents with the same number of decisions) and 5.75 and 7.00 validated inventions vs 2.75, but the strongest single artefact stays with isolated search (0.3488 vs 0.2380). About 95% of first reuses of a technology began with an agent seeing the object in the world rather than receiving a message: the memory lives in the environment. Four seeds per condition, game physics, one model.
:::

:::takeaways
- The native window grew to 1 million tokens, but reasoning over the whole window and robustness to length remain weak ([Opus 4.6](#w-opus46-launch-cluster); LOCA-bench, Chroma): the niche for swarm memory is not fitting more in, but not losing the thread.
- Memory beyond the window works without a swarm: one agent answers over corpora 22–40 times longer than its window ([RLM](#w-recursive-language-models)), and a coding agent with files beats published records on four of five long-context benchmarks ([Duke](#w-coding-agents-long-context)).
- The memory of real swarms lives in external structure: a claim graph ([Lean](#w-fermat-last-theorem)), a knowledge base with a curator agent ([ART](#w-anthropic-art-enzymes)), a shared folder ([CORAL](#w-coral)), a commit graph ([Agora](#w-agora-git-memory)), the environment ([SwarmWorld](#w-prev-swarmworld)). It carries leads between sessions, but in the ART campaign the detail was seen only by the agent that read the raw DNA.
- Shared notes raise answer accuracy with diminishing returns: 0.53 / 0.70 / 0.74 for 1 / 10 / 100 agents ([Ch. 4](#w-opus55-card)). Distributed facts do not add up: 30.1% vs 80.7% ([HiddenBench](#w-hiddenbench)), 61.2% → 18.1% from 2 to 100 agents ([Silo-Bench](#w-silo-bench)); forced exchange of facts helps.
- There are two direct comparisons of shared and private memory within a team, and they disagree: in the [ablation](#w-scaling-teams-or-time) private memory is slightly better (49.43 vs 48.62); in [ScaleMAS](#w-scalemas-substrate) a shared store with search gives 55.1% vs 46.8%. Whether shared memory helps depends on the task, the retrieval mechanism and what agents actually retrieve; a shared folder alone guarantees no gain. Open: how such memory grows at hundreds of agents; savings in context and the value of past experience must be measured separately ([UCLA](#w-persistent-memory-controlled-ablation)).
:::
