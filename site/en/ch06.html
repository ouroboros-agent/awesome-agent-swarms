Chapter 6

Swarm Memory

What does memory beyond a single model's window give a swarm? External memory helps a single agent too; shared team notes raise answer accuracy with diminishing returns, and facts distributed across agents do not add up without an exchange protocol.

Swarm memory is not reducible to the sum of context windows. Agents store and pass on knowledge through files, claim graphs, repositories and the shared environment. Three results need to be kept apart:

  • Working beyond the window. External memory helps a single agent too; by itself this is not a swarm advantage.
  • Joint accumulation of knowledge. In Anthropic's experiment with Opus 5.5, answer accuracy from the team's notes rises from 0.53 for one agent to 0.70 for ten and 0.74 for a hundred (Ch. 4). This is answer accuracy, not a measurement of memory capacity.
  • Pooling distributed facts. Knowledge spread across members does not guarantee a correct shared answer.

The chapter moves from the limits of the native window and a single agent's external memory to shared swarm artefacts, the pooling of distributed facts, and population and environment memory.

The native window grew; reasoning over it did not

A long window covers storage and retrieval, but not reasoning over the whole window (Claude Opus 4.6, card below). Quality falls with length even inside the window: in 2025 Chroma described "context rot" across 18 models (the longer the input, the less reliable the answer, and unevenly across positions), and LOCA-bench (HKUST, February 2026) showed an agent's accuracy dropping fast as its context grows from 8 to 256 thousand tokens with the task held fixed, with a clear benefit from context management (both works are in the table at the end of the chapter). This is the niche the swarm lays claim to: not fitting more in, but not losing the thread.

Memory through many calls: a single agent beyond the window

Memory beyond the window does not require a swarm. The text is moved into the environment (a variable, a file, a directory), and the model reads it in chunks, calls itself on fragments, or edits its own context as a document; this way a single agent already works with corpora of millions and trillions of tokens. These works show that "effective memory" exceeds the window by orders of magnitude, and they set the bar for a swarm: if one agent with a file system already handles a corpus of trillions of tokens, swarm memory has to deliver something beyond that.

Recursive Language Models

The model keeps text in a variable and calls itself on chunks of it: over a corpus of 6–11 million tokens (22–40 times GPT-5's window) it answers correctly 91.3% of the time; the sub-calls do not communicate with each other.

What they did. Alex Zhang, Tim Kraska and Omar Khattab (MIT CSAIL; preprint, 31 December 2025) proposed recursive language models (RLMs). The long text is placed in a variable inside an environment where the model executes Python code. The root model sees only the length and the beginning of the text, writes code that searches and filters it, and from that code calls a language model (itself or a cheaper one) on individual chunks. Sub-calls return strings, know nothing about each other, and in the main experiments ran one after another.

Results. - BrowseComp-Plus with 1,000 documents (6–11 million tokens, 22–40 times GPT-5's window of 272 thousand): RLM(GPT-5) answers correctly 91.3% of the time, while GPT-5 itself cannot take the input, an agent with BM25 retrieval scores 51.0% and a compaction agent 70.5%. - OOLONG-Pairs, where the answer depends on almost every pair of lines: F1 rises from 0.1 for GPT-5 to 58.0 at depth 1 and 76.0 at depth 3. - Quality still falls with length, only more slowly: on OOLONG the RLM drops from 84.5% at 8 thousand tokens to 46.0% at 1 million, GPT-5 from 92.1% to 31.1% already at 262 thousand. - Median gain across four tasks: +26% over the compaction agent, +130% over CodeAct with sub-calls, +13% over Claude Code (on Claude Opus 4.1); over the OpenCode coding agent on the same GPT-5 the margin is about 2%. - Cost per query is on average comparable to the base model, but with a heavy tail.

Why it matters. The work shows that "memory through many calls" far exceeds a single model's window, and it does so against baselines on the same GPT-5 (BM25 retrieval, compaction, the OpenCode coding agent). But this is not a swarm: sub-calls do not communicate, there is no speed-up (RLMs take longer), and much of the effect comes from simply moving the text into a programmable environment.

Caveats. Small test sets (20–150 examples), single runs without intervals, mostly synthetic tasks; on short inputs the plain model is better; deep recursion helps GPT-5 on the hardest task but mostly hurts Qwen3-Coder, and an independent reproduction (CUHK) found that depth 2 lowers accuracy. NeurIPS 2026 acceptance is according to the author's blog.

The University of Washington and Meta Superintelligence Labs (Shao and 12 more authors; preprint, 29 September 2026) propose "context language models": the context lives in a file that the model edits itself through bash, instead of a transcript compressed by an external harness. Without fine-tuning, an agent on Qwen3.6-27B with a 32 thousand-token window scored 59.4% on BrowseComp-Plus (11.4% higher than the best summarization baseline, at lower compute). The only swarm experiment: 6 GPT-5.6-Sol agents, one per repository, optimize interdependent Python packages for more than a day; the speed-up on held-out tests is 1.044× vs 1.026× for a swarm with summarization at the same spend. Subagents barely help: 44.2 vs 44.6 with a 32 thousand-token window, and only at 128 thousand 50.2 vs 47.3, at about +54% compute. The preprint is dated 29 September 2026, four days before the corpus cut-off; the swarm was run once.

Gandhi, Kumar and Neubig (CMU) with Chakraborty and Wang (Amazon AGI Labs; preprint, 7 May 2026) train a model to spawn copies of itself with a clean window. On synthetic crafting, a recursive agent with an 8 thousand-token window solves 95% of tasks and 88% of hard ones, almost as well as with a 256 thousand-token window, while a single agent at 8 thousand stays at 24% and 0%. When the single agent's window is large enough, it still solves only 20% of hard tasks against 88%, and on hard tasks solved by both, recursion is 2.5 times faster. On Oolong-Real the reward rises from 0.203 to 0.320 and on DeepDive success from 0.24 to 0.40, but there, on tasks solved by both, recursion is about 18 times slower and spends 561 thousand tokens vs 20 thousand. The prompt encourages delegation; the models are Qwen with 4 and 30 billion parameters.

Six more works of the same family are collected, with their numbers, in the table at the end of the chapter: MemAgent (the agent reads text in chunks and rewrites a short memory), Context-Folding from ByteDance Seed (folding a subtask into a brief summary), Recursive Agent Harnesses from PwC and Prime Agent from Prime Intellect, Princeton and MIT (recursive subagents), Cursor's Composer 2 (training together with chains of self-summaries), and Anthropic's engineering blog, which in September 2025 reduced practice to three techniques: context compaction, structured notes outside the window, and subagents with a clean context that return a brief summary.

Shared artefacts in real swarms

When there are many agents working for weeks, memory is no longer the window but what lies between agents: a claim graph, a repository, a shared folder, an index of notes. In 2026 such memory held several swarms together, and each case shows its cost. An example of accumulation is the knowledge base that up to 100 Opus 5.5 agents build in a day (Ch. 4): nearly all of the gain in answer accuracy on it comes by 10 agents, and going from 10 to 100 adds only 4 pp. Cursor, whose swarm wrote SQLite, explains its success by context efficiency: "We suspect the ability to scale the agent swarm comes from this context efficiency, more than from parallelism itself." A planner never implements and never clutters its window with details, a worker never plans, and a shared Field Guide is curated by the agents themselves; this is the author's hypothesis, without an ablation. Kimi K2.5 calls its swarm "proactive context management": each helper works in its own window and returns a single result. As early as 2025, Anthropic engineers wrote that the lead agent of their Research system stores its plan in external memory because context beyond 200 thousand tokens is truncated (Ch. 4). Below are Anthropic's enzyme-discovery campaign, where a dedicated agent maintains the shared knowledge base, and four more works that make such external memory an object of study.

A campaign of Claude Mythos 5 agents with a shared knowledge base found a new branch of enzymes in 21.5 hours, but the decisive detail was seen by one worker that read the raw DNA; 10 reruns missed it.

What they did. Anthropic (23 September 2026) tasked its agent system with finding new reverse transcriptase systems (enzymes that copy RNA into DNA) in a metagenomic protein database. Every role was played by Claude Code with Claude Mythos 5, while humans set the structure: five stages of the brief with scripted checks, worker–supervisor pairs, a report editor. Memory consisted of a shared version history and a knowledge base that a "curator" agent updated after each task; relevant entries from it were injected into the prompts of later agents.

Results. - Scale: in 21.5 hours without human intervention, 119 tasks (98 of them opened by the agents themselves), 949 sessions and 215.6 million tokens, excluding cache reads. The announcement's "roughly 950 agents" is the sum of short sessions in different roles: the system allowed at most 58 at once, and on average 3–4 were running (our estimate). - Discovery: a new branch of ART enzymes with an array of CRISPR-like repeats. The decisive step was taken by one worker that read raw DNA in its own window: neither the brief nor the task assignment asked about repeats. - Repeatability: in 10 reruns of the same campaign the array was never noticed. In a test of single models on the already found data, the strongest models found the array in at least 90% of attempts when the DNA was placed directly in the prompt, while working through files and tools the share fell to as low as 32% (Opus 5).

Why it matters. The campaign rests on shared memory maintained by a dedicated agent and shows its limit: the memory carried leads between sessions, but the detail was seen only by the agent that read the raw data itself. The hierarchy was set from above (Chapter 5), and there is no "single agent" or "team without a lead" control (Chapter 4): this is an application example, not a scaling measurement.

Caveats. A company report without peer review: the brief, the code and the skill library are unpublished, the lab experiments were done by humans, and, by the authors' own account, the enzyme's activity and the system's function have not been shown. Mario Rodriguez Mestre (University of Copenhagen) says his group studied these enzymes for years and discussed unpublished data with Claude; Anthropic replies that it knows of no publications on the system and did not train on users' conversations.

"Dozens" of Claude agents wrote a Lean 4 proof of Fermat's Last Theorem (13 million lines) in 11 days once they switched to the shared Prove2Me claim graph; there is no single-agent control.

Anthropic (blog, 4 September 2026; the project was led by Tianyi Peng, whose group at Columbia University builds Prove2Me): "dozens" of Claude agents, from 7 to 17 August 2026 (11 days), wrote the first complete machine-checked proof of Fermat's Last Theorem in Lean 4: 29,511 theorems, 13 million lines, about 6 billion output tokens; checked by the Lean kernel and by the independent nanoda kernel. The first attempts failed: agents "quickly lost track of the project's state and stopped collaborating effectively" (their work still accounts for about 7% of the final non-boilerplate lines). Prove2Me worked: a shared dependency graph of statements with a natural-language description of each, "particularly helpful for mitigating memory degradation"; agents checked other agents' statements before proving them. There is no single-agent control, the effects of model and platform are confounded, and the number of simultaneous agents and the cost are not disclosed; the proof relies on Mathlib.

Eight NVIDIA authors (Zhang, Dong et al.; preprint, 16 September 2026) built shared agent memory as a Git commit graph: every result, failure and check references its parents, and there are no roles. From 26 April to 8 May 2026, 13 workers (eight of them on Claude Opus 4.7, GPT-5.5 and GPT-5.4; the models of the other five were not recorded) took a frozen model from 3.3923 to 1.899 bits per byte (62% of the way to a trained GPT-2 124M), leaving 1,703 contributions, including 165 checks; the winner's lineage is 145 commits from 15 accounts. The gain per unit of compute was not measured: v1 proposed four equal settings, and v4 removed that table.

CORAL (Qu, Zheng, Zhou et al. from MIT, NUS, SMART and others; COLM 2026, preprint April 2026) replaces fixed evolutionary search with long-running agents that share a memory of attempts and notes. A single agent on Claude Opus 4.6 is not worse than OpenEvolve, ShinkaEvolve and EvoX on any of 11 tasks (strictly better on 9) and is strictly above the previous record on 6. Stanford (Mao, Mirhoseini et al.; preprint, 9 June 2026) removes the lead agent: peer agents take tasks from a queue and write findings into a shared context. On SWE-bench Verified with Gemini 3 Flash, two-agent DeLM and AOrchestra cost the same, $0.24 per task, while accuracy is 63.72% vs 55.26%; four agents give 66.08% at $0.47. When distributed knowledge does not add up

A second difficulty for swarm memory is not length but distribution. If facts are spread across agents, the swarm has to gather them, and for that someone has to ask what the others know. Two benchmarks from 2026 conferences (ICML and ACL) expose different failures of knowledge exchange: in HiddenBench, agents fail to elicit others’ unique facts; in Silo-Bench, they often answer before gathering the data or fail to converge. A third work adds a direct comparison of shared and private memory. An engineering view of the same problems comes from a Caura.ai and Ben-Gurion University group (table at the end of the chapter): the shared memory of an agent fleet breaks in four ways, and an evaluation of their production service recovered all provenance chains of depth 4 but found an isolation bypass and a conflict in the order of checks.

Li, Naito and Shirado (Carnegie Mellon; ICML 2026) took the "hidden profile" task from social psychology: each agent has shared facts and its own unique piece, and the correct answer is visible only to someone who puts everything together. Authors from Emory, Illinois Tech, Notre Dame and Cisco Research (Wu, Shu et al.; preprint, 27 March 2026) compare team size with accumulating experience through LLMA-Mem memory on MultiAgentBench. Population memory and environment memory

Memory can also be kept outside the agents: in an archive of other agents' trajectories, from which a new agent retrieves relevant experience, or in the world itself, where traces and structures remain. A CMU and Berkeley group tested the first approach, an MIT lab the second, on societies of up to 200 agents. Both yield gains, but neither measures how such memory grows with the number of agents. Other forms of shared memory (the Kosmos "world model", AgentFlow's growing memory shared by roles, and the exchange of hidden vectors in Latent Collaboration) are collected in the table at the end of the chapter.

A CMU and Berkeley group (Kim, Diaz, Arabzadeh et al.; preprint, 18 June 2026) pools trajectories of dozens of different models into a shared index, from which the next agent retrieves a piece of past experience. SwarmWorld: Stigmergic technological evolution in societies of language-model agents

In a shared environment where up to 200 agents leave structures, shared worlds yield more validated inventions (5.75 and 7.00 vs 2.75), but the strongest single artefact stays with isolated search.

SwarmWorld (Pal, Wang, Buehler; MIT, preprint, 26 August 2026): identical gpt-5.6-luna agents without roles live in a shared 72×54 grid environment and leave structures with executable programs that are tested after the agents are removed; the largest society is 200 agents in one world. By tick 3,200 (100 agents), shared worlds give portfolio resilience of 0.2474 and 0.2365 against 0.1794 for the control (the best of N isolated single agents with the same number of decisions) and 5.75 and 7.00 validated inventions vs 2.75, but the strongest single artefact stays with isolated search (0.3488 vs 0.2380). About 95% of first reuses of a technology began with an agent seeing the object in the world rather than receiving a message: the memory lives in the environment. Four seeds per condition, game physics, one model.

Takeaways

  • The native window grew to 1 million tokens, but reasoning over the whole window and robustness to length remain weak (Opus 4.6; LOCA-bench, Chroma): the niche for swarm memory is not fitting more in, but not losing the thread.
  • Memory beyond the window works without a swarm: one agent answers over corpora 22–40 times longer than its window (RLM), and a coding agent with files beats published records on four of five long-context benchmarks (Duke).
  • The memory of real swarms lives in external structure: a claim graph (Lean), a knowledge base with a curator agent (ART), a shared folder (CORAL), a commit graph (Agora), the environment (SwarmWorld). It carries leads between sessions, but in the ART campaign the detail was seen only by the agent that read the raw DNA.
  • Shared notes raise answer accuracy with diminishing returns: 0.53 / 0.70 / 0.74 for 1 / 10 / 100 agents (Ch. 4). Distributed facts do not add up: 30.1% vs 80.7% (HiddenBench), 61.2% → 18.1% from 2 to 100 agents (Silo-Bench); forced exchange of facts helps.
  • Open: no work measures how swarm memory grows with the number of participants at hundreds of agents with a shared store; in the only direct comparison of shared and private memory within a team, private memory is slightly better (49.43 vs 48.62, ablation).
